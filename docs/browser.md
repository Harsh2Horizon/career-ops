# Browser adapters and assisted applications

Use the officially supported Codex browser/computer-use capability for authenticated or unusual flows when available. Inspect available tools in each session; names and surfaces can change. This session exposed `mcp__cua_repl` with native Chrome and Node Playwright packages. No browser MCP/API credential is hardcoded.

The CLI's `BrowserDriver` protocol has open, snapshot, fill, next, submit and close. `PlaywrightDriver` implements JSON-lines RPC to an installed Node Playwright. No browser cookies, storage_state, passwords or session files are persisted. The program restricts navigation to exact approved HTTPS hosts and loopback in explicit mock mode; resource hosts are separately configured. Network GET retries are bounded; browser submission is never retried.

The semantic fallback observes visible labels/aria-labels/placeholders/names and exact dropdown options. Built-in support covers ordinary text/email/phone controls, textareas, native selects, file inputs and explicitly verified checkboxes. Radio groups, custom dropdowns, iframe/file widgets, authentication, MFA and CAPTCHA require manual handling or a new adapter. Greenhouse/Lever/Ashby/company forms may work when they expose supported controls; that is not a claim of tested live ATS coverage. Workday and login-dependent YC/LinkedIn/Indeed flows are assisted, not certified automatic integrations.

To add an adapter, implement BrowserDriver, inject its factory into ApplicationService, and add a local mock reproducing the actual failure. Prefer semantic controls over selector-only matching. Preserve review snapshots, verify uploads and filled values, reserve before final submit, and capture positive receipt evidence. Do not copy final-submit logic into an adapter.

For a computer-use flow, the agent must independently apply the same policy: verify the selected job/current PDF; inspect all fields; map exact verified facts; stop for approval; record the concrete review; submit once only with that job's approval; capture evidence; persist the status. The current CLI does not offer a general authenticated computer-use RPC adapter or automatic import of arbitrary native UI snapshots. Use it for candidate/job/document preparation and tracker reconciliation, and keep approval/receipt evidence in the local application record. Do not claim a computer-use action occurred from a Playwright test-double result.

Real multi-step navigation requires a verified site-specific adapter or computer-use/manual handling. The generic CLI never clicks an unknown real Next/Continue control because it could be a final submission. Automatic Next navigation is limited to the known local mock. Website-specific save-progress controls are also handled manually.
